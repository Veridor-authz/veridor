# Adopters

Organizations that **currently and actively run Veridor** in a setting that matters to them: a CI
gate that decides merges or deploys, a staging pipeline against a real API, or a security evaluation
that reached a decision.

That follows the [CNCF TOC's definition of an adopter](https://github.com/cncf/toc/blob/main/FAQ.md#what-is-the-definition-of-an-adopter)
("currently and actively, successfully leverages that project"); the three settings are Veridor's
own. Stars, forks, blog mentions and "we tried it once" do not qualify. An honest empty list is worth
more than a padded one.

_There are no listed adopters yet._

## Adding yourself

Open a pull request adding a row. Say what you point it at and, if you can, what it caught or what it
cost you. A contact who can confirm the entry is helpful; it is not required.

- **Type**: End-User Organization, Service Provider, Project or Consultancy, as the
  [CNCF project template](https://github.com/cncf/project-template/blob/main/ADOPTERS.md) defines
  them.
- **Adoption Level**: Production (a CI gate that decides merges or deploys), Staging, or Evaluation
  (a security evaluation that reached a decision), as defined above.
